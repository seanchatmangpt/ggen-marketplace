## Findings (disclosed, unfixed — outside this lane's surfaces or precedent-level)

1. **Output-path override does not exist** (confirms L10's reported finding by
   re-derivation): the render target is the template `to:` line
   (`src/shacl_zod_schemas.js`); a consumer cannot retarget from ggen.toml. cmms wanted
   `.ts`, received `.js`; the `.ts` beside it is hand-authored. Now documented in README +
   pack.toml with the retarget recipe (vendor the template, edit `to:`).
2. **Basename collision hazard when composing both packs**: this pack renders
   `src/shacl_zod_schemas.js`, shacl-projection-pack renders `src/shacl_zod_schemas.ts`.
   TypeScript's `.js`-specifier→`.ts` remapping prefers the `.ts` file, so a consumer
   importing `./shacl_zod_schemas.js` resolves to the law pack's stub and gets TS2305
   `no exported member` (witnessed: rc=2 with both files present, rc=0 after moving the
   stub away). cmms is in exactly this state (both files present). Resolution options
   (retarget one template's `to:`, or distinct basenames) touch the law pack and cmms —
   not this lane's owned files.
3. **Vocabulary interop gap**: this pack's SPARQL selects `sp:ZodSchema` / `sp:schemaName` /
   `sp:projectionName`; the law pack's qualification individuals and its own template use
   `shp:SchemaModel` / `shp:className`. Same namespace
   (`http://seanchatmangpt.github.io/packs/shacl-projection#`), different properties —
   a consumer supplying only law-pack-shaped individuals gets the silent `.js` stub.
   Documented in README; not silently papered over.
4. **Enum member order is not deterministic from the graph**: the template builds
   `z.enum` from GROUP_CONCAT without an intra-group ORDER BY; witnessed
   `["closed","draft","open"]` for source order `("draft" "open" "closed")`. Enum order is
   semantically inert in zod but the rendering is not source-stable.
5. cmms was NOT re-synced (running ggen sync there writes consumer files outside OWNED
   FILES). The version bump and template unchanged-ness (sha256 above, unchanged from
   baseline) mean the rendered bytes are identical; only pack.toml metadata changed.
   Standing of cmms integration: UNVERIFIED this session, expected unchanged.
