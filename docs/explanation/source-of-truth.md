# Explanation: source of truth

A pack should answer **what is admitted?** before it answers **what file was emitted?** RDF is semantic source, the manifest gives pack identity, templates/project rules manufacture consequences, and gates refuse invalid facts before writes.

For marketplace distribution, the admitted `packs/` bytes in this repository are canonical. A pack may have been imported from `ggen`, GymAct, AutoFDE Lab, or another repository, and another repository may carry a byte-identical mirror. Those relationships are provenance after marketplace admission. Historical branch ancestry cannot silently move marketplace source authority away from `seanchatmangpt/ggen-marketplace`.

## Semantic authority and manufacturer identity are different

`marketplace.toml` declares marketplace operational law, including the exact ggen release identity and asset digests used for qualification. That configuration must be admitted before execution. ggen qualifies/manufactures from canonical pack source; execution does not make the ggen repository a second authority for marketplace pack bytes.

The chain is:

```text
pack RDF / templates / gates in ggen-marketplace
        ↓ admission
canonical marketplace pack source
        ↓ admitted ggen/toolchain/config identity
qualification / deterministic manufacture
        ↓
consumer consequence
        ↓ native consumer verification
receipt / replay / standing
```

Each arrow has a different proof obligation.

## Documentation source authority

Documentation follows the same rule. Hand-maintained prose is appropriate for tutorials/how-tos/explanations and domain narrative, but exact reference/navigation facts should be projected from canonical semantic/configuration sources when practical.

For the marketplace book:

```text
docs/book.ttl
   ↓ mdbook-pattern-language-pack + ggen
book.toml + docs/SUMMARY.md
   ↓ mdbook
published book
```

`docs/SUMMARY.md` is therefore a generated projection, not an editing surface. The Pages workflow deliberately removes it and manufactures it from `docs/book.ttl` before building the book.

Level-5 pack documentation has the same expectation: generic Diátaxis structure can be generated by `pack-maturity-pack`; domain-specific facts must come from the composing pack's admitted source rather than plausible prose invented by the generator.

## Why there is no hand-edited catalog

A hand-maintained `catalog.json` would duplicate manifest facts and eventually drift. `scripts/marketplace.py catalog` computes a deterministic projection whenever machines or humans need catalog JSON.

The same principle applies to versions, timeout/worker law, runtime release commits, asset digests, pack class facts, and generated documentation navigation: when there is an executable canonical source, documentation should link/project rather than copy volatile values.

## Repair direction

When an emitted artifact disagrees with canonical source:

```text
repair semantic/config/query/template/gate source
→ re-admit
→ regenerate
→ re-verify
→ re-receipt
```

Do not bless drift in place.

When two packs assert the same semantic truth independently, use [class closure and consolidation](class-closure-and-consolidation.md) to canonicalize the shared authority while preserving domain/runtime differences that are not equivalent.
