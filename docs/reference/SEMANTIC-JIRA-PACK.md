## What the pack provides

`semantic-jira-pack` is the ontology-native work-order substrate of the fleet:
admitted work orders, SHACL-constrained shape court, SPARQL admission gates,
and the A2A skill-exposure mechanism, all projected through `ggen_igniter`.

- **`sj:` vocabulary** (`ontology.ttl`): work orders, actions, authorities
  (`sj:CodeWorkAuthority`, `sj:StrategicObjective`, `sj:GoalCheckpoint`),
  origin authority (`sj:originAuthority`, exactly-one per work order),
  admission digests, standing vocabulary, and A2A exposure terms
  (`a2a:skillName`, `a2a:ashAction`, `a2a:consequence`, `a2a:exposed`,
  `a2a:generatedBy`).
- **SHACL shapes** (`shapes/work-order.shacl.ttl`,
  `execution-descriptor.shacl.ttl`, `pack.toml`-declared `proposition.shacl.ttl`
  and others): `sj:WorkOrderShape` (required `dcterms:identifier`, title,
  `sj:originAuthority`, standing, `sj:authorityCeiling` with
  `sh:minCount 1`), `sj:FridayWorkOrderShape` (checkpoint subjects), origin
  authority / admission-digest shapes (`sj:WorkOrderOriginShape`,
  `sj:AdmissionDigestShape`).
- **Admission gates** (`gates/010..066`): SPARQL SELECT gates over the pack
  graph — work-order subjects (010), work orders (020), properties (030),
  nodes (0 exercisable nodes, 040), description integrity (045),
  ALIVE-receipt crown (046), provider-neutral admission (047), frontier
  (050), standing projection (055), and the A2A gates (060-065):
  exposed skills, state map, refusals, targets, attributes, and the
  target-pack contract. `epoch_boundary.rq` closes the set.
- **The `060_a2a_skills` mechanism** (`gates/060_a2a_skills.rq`): exposes
  `sj:Action` individuals as A2A skills only when they carry
  `a2a:exposed true`, name an Ash action, declare a consequence, and were
  generated by an admitted `gi:standing "ALIVE"` generator capability;
  forbidden-capability actions are removed by `MINUS` (not
  `FILTER NOT EXISTS` — a SPARQL 0.3.12 limitation noted in the gate), so the
  gate stays correct even if the SHACL court were bypassed.

## How fleet repos consume it

- **Work-order admission**: `mix semantic_jira.admit_candidates` (in
  `ggen_igniter`) takes a JSONL file of work-order candidate maps (16 required
  keys: `identity title description subject repository base_sha standing
  evidence_ceiling promotion_rule replay_identity required_courts
  required_evidence acceptance falsifiers projections origin_authority`).
  One verdict per non-blank line; a candidate is admitted only when the
  kernel `SemanticJira.admit_work_order/1` passes AND its `origin_authority`
  resolves in the pinned authority index — prose never admits. Candidate-bounds
  refusals: `refused_candidate` (`literal_standing`,
  `ceiling_exceeds_construct` — any `DO`/`EXECUTE`/`ACTUAT`/`MERGE`/`PUBLISH`
  /`DEPLOY`/`PUSH`/`RELEASE`-prefixed ceiling), duplicate identity, and the
  opt-in epoch gate via `--epoch-manifest` (`REFUSED_EPOCH_*`, fail closed).
  Exit 0 when every line was judged (a refusal is a verdict); 2 invalid
  invocation; 1 authority index unavailable.
- **SHACL courts**: fleet repos run the pack's `shapes/*.shacl.ttl` against
  their own graphs. The castle repo is the conformant-instance precedent: it
  consumes the `sj:` vocabulary's `GoalCheckpoint` successor shape
  (`docs/sjira/v26.10.8/goal.ttl`, 129 lines, `main` @ `313d67e`) and renders
  its crown-gate skills from the pack-conformant surface (see
  [`FLEET-SEMANTIC-MAP.md`](FLEET-SEMANTIC-MAP.md), castle rows).
- **A2A agent cards / skills**: the `060_a2a_skills` gate plus
  `061_a2a_state_map` / `062_a2a_refusals` / `063_a2a_target` /
  `064_a2a_attributes` / `065_target_pack_contract` define the
  skill-exposure surface fleet repos project into `.well-known/agent-card.json`
  and `skills.ttl` (see [`FLEET-SEMANTIC-MAP.md`](FLEET-SEMANTIC-MAP.md)).
