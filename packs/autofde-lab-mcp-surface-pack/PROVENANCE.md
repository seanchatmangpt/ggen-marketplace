# Source provenance

`ontology.ttl` is **derived, not authored**. It is regenerated by
`scripts/derive_autofde.py`, which reads two real files in the AutoFDE Lab
working tree at `/Users/sac/gym-ecosystem/vendor/autofde-lab`:

| Fact in the graph | Real source |
| --- | --- |
| operation titles, descriptions, parameter names, JSON types, required sets | `src/autofde_lab/openclaw_bridge.py` → `_TOOL_SPECS` (parsed via `ast`, so no scikit-decide import is needed) |
| `urn:gymmcp:replaySafe` per operation | `integrations/openclaw/openclaw.plugin.json` → `toolMetadata.*.replaySafe` |
| server name and version | `openclaw_bridge.py` → `SERVER_NAME`, `SERVER_VERSION` |
| namespace `autofde_lab` | `openclaw_runtime.py` → `TOOL_NAME_PREFIX = "autofde_lab_"` |

Re-derive with:

```
python3 scripts/derive_autofde.py ontology.ttl
```

## Consequence classification

The gym's own plugin metadata is the ground truth, not a guess: a tool AutoFDE Lab
marks `replaySafe: true` (`catalog`, `describe`) is classified
`<urn:gymact:consequence:read>`; a tool it marks `replaySafe: false` and `optional`
(`match`, `run`) constructs or executes and is classified
`<urn:gymact:consequence:do>` with `urn:gymmcp:requiresAdmission true`.

## Naming difference, stated rather than hidden

The live bridge advertises tools as `autofde_lab_catalog` (underscore separator, and
a second legacy `skdecide_` spelling). This pack projects the MCP convention
`autofde_lab.catalog`. The projection is of the operation *surface*, not a drop-in
replacement for the running bridge's exact wire names.

## Authority boundary

This pack manufactures intents and grants no runtime authority. `match` and `run`
carry `requiresAdmission`; `gates/010_mcp_authority_boundary.rq` refuses manufacture
of any DO operation that does not. Consequential execution stays behind GymAct/BRCE
admission, external to this pack — the same boundary
`chatgptgym-gymact-bridge-pack` establishes, expressed as a graph obligation so it
travels between gyms.
