# castle-pack

Ontology-first source for CASTLE.

The pack projects the admitted architecture/goal bindings into a consumer `src/generated.ts` and `docs/GENERATED_ARCHITECTURE.md`. Runtime algorithms remain consumer consequences; this pack is the semantic authority for the generated component inventory, authority boundaries, and default prohibited-goal priorities.

Canonical flow:

`GOAL -> DfCM inverse construction -> dependency CONSTRUCT -> AutoFDE-Lab planner ensemble -> POWL v2 -> bounded GymAct -> OCEL v2 -> BLAKE3 receipt -> replay/invariant compilation`.

Planner and CONSTRUCT outputs are candidates only. GymAct execution is constrained to explicit owned/authorized test envelopes. Consequential defensive actuation remains BRCE receipt-bound.
