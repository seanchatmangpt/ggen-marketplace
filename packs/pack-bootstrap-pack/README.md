# pack-bootstrap-pack

Generates a new ggen pack's manifest, ontology, gates, verifies, and registry
template from a census of an existing project ontology. Legacy profile
(no `gp:profile` in the graph).

## Shape

```
pack.toml                      # legacy-profile manifest ([pack] name/version/description only)
ontology.ttl                   # bp: meta-vocabulary + census terms
queries/meta.rq                # single row: the bp:BootstrapTarget
queries/source_classes.rq      # one row per source class, ORDER BY ?classIri
queries/source_properties.rq   # one row per source property, ORDER BY IRI
queries/capability_rows.rq     # one capabilityId per source class, ORDER BY IRI
gates/010_source_census.rq     # witness gate: >= 1 row PASS
gates/020_capability_surface.rq# witness gate: >= 1 row PASS
gates/030_output_target.rq     # witness gate; a targetDir lexically containing
                               # "pack-bootstrap-pack" yields 0 rows -> run refused
verify/010_source_census.unbound.rq  # offender query: ZERO rows PASS
verify/020_capability_surface.unbound.rq # offender query: ZERO rows PASS
templates/*.eex                # per-template outputs (below)
```

`ontology.ttl` defines the `bp:` vocabulary
(`https://ggen.dev/ontology/pack-bootstrap#`): `bp:BootstrapTarget` with
`bp:packName`, `bp:packVersion`, `bp:nsBase`, `bp:targetDir`, plus census terms
`bp:SourceClass`, `bp:SourceProperty`, `bp:capabilityId`.

## Input contract

The `--ontology` passed to a bootstrap run is the INPUT graph. It must declare
exactly one `bp:BootstrapTarget` individual:

```turtle
@prefix bp: <https://ggen.dev/ontology/pack-bootstrap#> .
@prefix my: <https://example.com/my-domain#> .

<urn:bootstrap:my-domain-pack> a bp:BootstrapTarget ;
    bp:packName "my-domain-pack" ;
    bp:packVersion "26.10.20" ;
    bp:nsBase "https://ggen.dev/ontology/my-domain#" ;
    bp:targetDir "packs/my-domain-pack" .
# ... plus the source classes (rdfs:Class / owl:Class) to census.
```

## Per-template invocation

From a built ggen_igniter checkout (`mix compile` done), one sync per output
file. `<PACK_DIR>` is this directory; `<INPUT>` is the input ontology above;
`<OUT>` is the new pack directory (`bp:targetDir`). All six invocations share
the same query set; only `--template`/`--out` change:

```
mix ggen_igniter.sync --pack-dir <PACK_DIR> --ontology <INPUT> \
  --query meta=queries/meta.rq \
  --query source_classes=queries/source_classes.rq \
  --query source_properties=queries/source_properties.rq \
  --query capability_rows=queries/capability_rows.rq \
  --template templates/<T>.eex --out <OUT>/<F>
```

| `--template` | emits |
|---|---|
| `templates/pack_toml.eex` | `<OUT>/pack.toml` |
| `templates/ontology.eex` | `<OUT>/ontology.ttl` (minimal `sj:` graph, one `sj:capabilityId` per source class, sorted by IRI) |
| `templates/gate_census.eex` | `<OUT>/gates/010_source_census.rq` |
| `templates/verify_census.eex` | `<OUT>/verify/010_source_census.unbound.rq` |
| `templates/template_ontology.eex` | `<OUT>/templates/ontology.eex` (a NEW EEx template — metatemplate) |
| `templates/template_registry.eex` | `<OUT>/templates/registry.ex.eex` (a NEW EEx template — metatemplate) |

`scripts/bootstrap_pack.sh <input.ttl> <out-dir>` (repo root, requires
`GGEN_IGNITER_DIR`, default `~/ggen_igniter`) runs all six invocations.

The two metatemplates emit `.eex` text: their EEx markers are produced from
concatenated pieces (`"<%" <> "="`, `"%" <> ">"`) inside the template's script
block, so generated templates carry literal markers that are NOT executed at
bootstrap render time.

## Gate convention

`gates/*.rq` are witness-reporting (>= 1 row PASS, zero rows FAIL — ADR 0010
keeps offender-shaped queries in `verify/`). Gate 030 therefore expresses the
self-reference refusal as a witness: every ACCEPTED `bp:targetDir` emits a row;
a targetDir lexically containing `pack-bootstrap-pack` (the bootstrap pack's
own directory) yields ZERO rows and the run fails/refuses.

## Falsifier

A generated pack must itself pass a `mix ggen_igniter.sync` run:

1. the generated pack's gates pass (>= 1 witness row each),
2. the generated pack's verify queries return zero rows,
3. the sync receipt is `:alive`,
4. a second run over the same input is byte-identical (no timestamps in any
   generated bytes).

Run it: bootstrap into a scratch dir, then point `--pack-dir` at the generated
pack with its own emitted ontology and re-run the census templates above
against it; then re-run and `cmp` the outputs.
