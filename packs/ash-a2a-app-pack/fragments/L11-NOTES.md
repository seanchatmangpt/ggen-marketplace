## Coordinator seams (resource.ex.tmpl is shared)

1. For each resource with `aap:pubSub`, add to `use Ash.Resource` options:
   `fragments: [<Resource>.L11PubSub]`
   (fragment declares `notifiers: [Ash.Notifier.PubSub]`; many-extension kind per
   deps/spark/lib/spark/dsl/fragment.ex:28-60, ash/resource.ex:20-31).
2. Simple (no-DSL) notifiers cannot ride a fragment: `simple_notifiers` is a `use` opt
   (ash/resource.ex:34, persisted at :132). Add
   `simple_notifiers: [<aap:notifier moduleName>, <aap:simpleNotifier ...>]` to the
   `use Ash.Resource` line.
3. Add `Demo.PubSubServer.children()` to the app supervisor (Phoenix.PubSub with name);
   mix.exs needs `{:phoenix_pubsub, "~> 2.1"}`.
4. Fragment load order: fragments list must include `Resource.L11PubSub` so the
   pub_sub section merges; the resource must be compiled after the fragment.

## Known gaps

- Function options (filter/transform) are remote captures `Mod.fun` only; modules must be
  handwritten or generated by another lane. No anonymous fns.
- `requires_original_data?/2` and `load/2` notifier callbacks not modeled.
- Per-action `notifiers:` option (actions/shared_options.ex:92) not modeled (action
  templates are shared).
- Nested topic alternatives via raw `aap:pubTopicTerm` only.
- Bridge payload is minimal (resource/action/id); no task snapshot encoding.
- Publication identity uses node IRI order (ORDER BY ?pub_id), not declaration order.
- Notifier file/server inDomain uses `aap:inDomain` on the PubSubServer node.
- Gates: SPARQL gate coverage unrun; Tera `is starting_with` unrun.
