# pptx-presentation-pack

Reusable semantic PowerPoint manufacture for `ggen_igniter`.

```text
consumer deck.ttl
  -> SPARQL gates (deck / slides / blocks)
  -> ggen_igniter
  -> deck.json + render.mjs
  -> PptxGenJS
  -> .pptx + speaker notes
```

The pack is CONSTRUCT-only. It defines no external DO authority, does not claim generated bytes are correct merely because they exist, and does not own a consumer's deck facts.

## Consumer contract

Model one `pres:Presentation`, ordered `pres:Slide` resources, and ordered `pres:Block` resources using `https://ggen.dev/ns/presentation#`.

Supported renderer layouts in v0.1.0:

- `hero_flow`
- `agenda`
- `source_chain`
- `triad`
- `pipeline`
- `pairs`
- `graph`
- `split`
- `chain`
- `stages`
- `timeline`
- `flow`
- `bullets`
- `three_part`

The layout vocabulary is intentionally small. Extend it only when a real deck shape cannot be composed from an admitted layout.

## Manufacture

Use the pack's templates with a consumer ontology:

```bash
mix ggen_igniter.sync \
  --engine sparql \
  --pack-dir /path/to/pptx-presentation-pack \
  --ontology /path/to/deck.ttl \
  --template /path/to/pptx-presentation-pack/templates/deck.json.eex \
  --out tmp/deck.json

mix ggen_igniter.sync \
  --engine sparql \
  --pack-dir /path/to/pptx-presentation-pack \
  --ontology /path/to/deck.ttl \
  --template /path/to/pptx-presentation-pack/templates/render.mjs.eex \
  --out tmp/render.mjs
```

Then execute the generated renderer with an admitted PptxGenJS runtime. PptxGenJS 4.0.1 is the currently qualified consumer target for this pack; the consumer should pin it explicitly.
