# Pack Consolidation Court

This pack makes marketplace consolidation an admitted, replayable semantic operation rather than a one-time directory cleanup.

## ERRC

- **Eliminate** duplicate semantic authorities when two packs own the same identity/law surface. Compatibility directories may remain during migration, but only one pack is canonical.
- **Reduce** repeated ontologies/facts by extracting one shared source of truth while retaining useful projections, adapters, and qualification surfaces.
- **Raise** composition quality: every consolidation family names its canonical authority, disposition, reason, migration obligation, and status; gates fail closed on ambiguous classifications.
- **Create** meta-pack/discovery surfaces for legitimate pipelines and a generated ERRC plan from the same RDF facts.

## Dispositions

`HARD_MERGE | EXTRACT_SHARED_ONTOLOGY | META_COMPOSE | DEPRECATE_INSTANCE | KEEP_DISTINCT | UNKNOWN_WITH_REASON`

## New-pack admission law

Before manufacturing a new pack, test whether an existing canonical pack, projection/profile, or lawful composition already owns the proposed semantics. A new directory is not evidence of a new capability class. If the existing topology is insufficient, add a `pcc:ConsolidationRelation`/candidate rationale and preserve the distinction explicitly.

## Current first tranche

The court records the high-confidence families found in the 2026-08-26 review: pack construction, runtime-evidence authenticity, DfCM decision law, wasm4pm facts, observation/memory law, evidence-capital policy, autonomic manufacturing, repo lifecycle, clap-noun-verb, and versioned ecosystem release instances.

This PR starts migration where compatibility-preserving changes are safe. Open `EXTRACT_SHARED_ONTOLOGY` items remain obligations until their generated consumers/tests are rewired to the canonical facts; the court intentionally does not call those ALIVE prematurely.
