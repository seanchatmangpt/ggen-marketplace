# Tutorial: manufacture a dual-RevOps Ash option

Start from an admitted existing structure and describe several reversible candidate structures. Bind each candidate to one or more pack options instead of selecting a single implementation prematurely. The pack projects Ash surfaces, dual revenue semantics, OCEL value evidence, and a regeneration path.

The generated consequence must preserve `RevenueFromCustomer` and `RevenueForCustomer` as distinct evidence objects. Consumer refinements may be promoted only when generalized, then regenerated consumers must requalify.
