## Source provenance

`ontology/ggen-ecosystem.ttl` is **derived, not authored**. It is regenerated by
`families/ggen-ecosystem/derive_ggen.py`, which shells out to the real installed
`ggen` binary and reads its own documented introspection flag:

```
ggen graph --introspect     # "Introspect CLI capabilities as JSON Schema array for LLM tool-calling"
```

Against `ggen 26.8.28` this yields 82 operations and 91 parameters. Operation names,
parameter names and JSON types are read from that live output verbatim; descriptions
are the first line of each command's own help text, whitespace-collapsed.

Re-derive with (note the module output path inside the kernel pack):

```
python3 families/ggen-ecosystem/derive_ggen.py ontology/ggen-ecosystem.ttl
```

## Consequence classification rule

Stated so it is auditable rather than hidden. An operation is
`<urn:gymact:consequence:do>` when its terminal verb segment is one of:

```
init init-self install lock add remove new enable run set load derive export register resolve materialize
```

Everything else is `<urn:gymact:consequence:read>`. This yields 63 READ / 19 DO.
Ambiguity is resolved toward DO, because misclassifying a consequential call as
observational is the failure that matters — a READ misfiled as DO merely costs an
unnecessary admission check, while the reverse leaks authority.

The rule is a *heuristic over real help text*, not a fact ggen itself publishes:
ggen's `--introspect` output does not currently carry a consequence class. That gap
is itself the finding — a CLI that already emits LLM-tool-calling schemas emits no
read/write classification with them, so any MCP host wrapping it cannot tell which
of the 82 tools mutate the working tree.

## Authority boundary

All 19 DO operations carry `urn:gymmcp:requiresAdmission true`.
`gates/010_mcp_authority_boundary.rq` returns zero rows against this module graph
and refuses manufacture if any DO operation loses that obligation. The module
projects intents only; it invokes nothing.

## Regeneration cadence: live-introspect

The ggen CLI's surface is re-readable on demand from the tool itself, so this
module is regenerated whenever the ggen verb surface changes (and the module's
`dct:hasVersion "26.8.28"` must be bumped to the introspected binary's version by
the script's source of truth). This differs from the autofde-lab family's curated
cadence — see `families/autofde-lab.md`.
