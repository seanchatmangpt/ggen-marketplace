# Why EXPLORE needs a hypergraph

A task list loses the multiplicative value created when several already-ALIVE capabilities become composable. A simple graph also understates the search space because many useful candidates require three or more simultaneous inputs: live evidence plus currentness plus yield calibration, or marketplace manufacture plus public ontology plus replay.

R30 therefore treats capabilities as reusable nodes, compositions as hyperedges, and executable candidates as induced option capital. Failed or unsupported edges remain typed topology. The frontier deliberately retains candidates with different reuse, capability-space delta, qualification strategy, and marketplace-support state so a later SELECT boundary can choose with evidence rather than silently destroying alternatives during exploration.

This turns verification into search: a falsifier can reject one edge, expose a missing primitive, or promote another composition without declaring the capability graph failed. The result is a compounding exploration substrate rather than a queue of isolated improvements.
