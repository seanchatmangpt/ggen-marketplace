# Why discovery ledgers need realization currentness

An Innovation Capital Ledger is useful only if downstream manufacture can change the standing of previously discovered opportunities. During R27 qualification, the GitHub ControlOutcome observation opportunity was independently implemented and merged by another cell. A static discovery ledger would continue calling that item novel/open even though its capability already existed on default.

R28 turns this race into measurable topology. It detects stale-open opportunities, binds realized capabilities to exact merge containment, measures time-to-realization and closure rate, and distinguishes concurrent default movement from loss of qualified work. This makes fast autonomous manufacturing safer: high parallelism can continue without requiring a single serialized planner, because exact lineage and currentness sensors reconcile what other cells realized.

The law is asymmetric: a merge can close an opportunity only with exact qualified-subject and containment evidence. An inferred adjacency or similarly named feature does not count as realization.
