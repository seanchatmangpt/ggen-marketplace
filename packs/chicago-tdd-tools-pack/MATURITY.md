## Fan-out mechanism (examples/ and playground/)

Unlike `readme-diataxis-pack`'s `example-file.tmpl`/`playground-file.tmpl`
(a generic template with a row-parameterized `to:` path fanning out to
many files from one unbounded `SELECT`), this pack's 4 templates each have
a **fixed** `to:` target — `cli_boundary_tests.rs.tmpl`'s row loop fans out
`#[test]` fns *within* one file, not across many output paths. This is a
real structural difference from the exemplar's mechanism, not a gap to
paper over: `ctt:CliBoundaryTest` individuals are proof-suite members of
one generated test module, not standalone files.

`examples/consume-chicago-tdd-tools-pack/` and `playground/SCRATCH.md`
still follow the exemplar's *intent* (self-referential, grounded in real
primitives, runnable): the example attaches this pack via the documented
local-path convention and declares two real `ctt:CliBoundaryTest`
individuals against the same `receiptctl`-shaped binary the pack's own
`ontology.ttl`/`qualification/consumer.ttl` already target; verified this
session with a real `ggen sync run` (8 `#[test]` fns generated). The
playground shows how to add a new individual and re-run `ggen sync run`,
and contrasts this pack's `CliHarness`-based boundary-test shape against
the real `config_test!` macro (`chicago_tdd_tools::core::macros::config_test`)
that `star-toml-pack` targets instead — naming, not inventing, the
boundary between the two packs' real domains.

## Admission — negative refusal receipt (real, this session)

The prior session's negative-admission-refusal claim was flagged UNVERIFIED because the
scratch fixture it used was never committed and no longer existed to re-run, per this
repo's `dfcm-pack` standing law (`packs/dfcm-pack/README.md`): "ALIVE requires observed
execution against the exact admitted subject plus a receipt" and "UNKNOWN is not
admitted." A fresh deliberately-broken fixture was built this session
(`/tmp/ctt-admission-check/broken-fixture.ttl`, untracked, never committed) with one
individual per gate designed to trip it:

- `ctt:broken-missing-required` — omits `ctt:expectExitCode` and `ctt:coversAxiom` (targets `010_required.rq`).
