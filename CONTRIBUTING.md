# Contributing

Contributions should change one coherent marketplace boundary at a time: add/update a pack, improve a shared kernel/capability, change marketplace control law, consolidate a proved family overlap, or improve a bounded documentation contract.

## Before editing

Read:

- [`AGENTS.md`](AGENTS.md)
- [`docs/reference/pack-contract.md`](docs/reference/pack-contract.md)
- [`docs/reference/pack-classes.md`](docs/reference/pack-classes.md)
- [`docs/reference/level5-maturity-contract.md`](docs/reference/level5-maturity-contract.md) when maturity/standing is affected
- the relevant Tutorial/How-to/Reference/Explanation pages.

For imported packs, preserve existing semantics/provenance unless the purpose is explicitly a behavioral modernization or consolidation.

## Pack changes

Every admitted pack keeps manifest and RDF authority self-contained under `packs/<pack-name>/`. Projection packs carry templates; semantic packs may intentionally omit templates; project packs may carry `ggen.toml`, split RDF, templates, queries, rules, fixtures, and pack-owned verification surfaces. Optional gates remain inside the pack boundary.

The directory name must equal `[pack].name`; versions use SemVer; descriptions are non-empty. Never commit consumer-generated corrections as a substitute for fixing admitted RDF/query/template/gate/project source.

If the change adds semantic truth already owned by a sibling, stop and evaluate class closure instead of creating a second authority. Use an umbrella/profile when composition/default selection is the actual need.

## Local acceptance

Admit operational configuration before qualification:

```bash
bash scripts/admit-config.sh marketplace.toml /tmp/ggen-marketplace-admitted.json
python3 scripts/marketplace.py validate
python3 scripts/marketplace.py catalog > /tmp/catalog-a.json
python3 scripts/marketplace.py catalog > /tmp/catalog-b.json
cmp /tmp/catalog-a.json /tmp/catalog-b.json
python3 scripts/marketplace.py fingerprint
GGEN_MARKETPLACE_ADMITTED_CONFIG=/tmp/ggen-marketplace-admitted.json \
  bash scripts/qualify-marketplace.sh \
  /tmp/ggen-marketplace-admitted.json \
  /tmp/ggen-marketplace-qualification.json
```

Do not duplicate runtime versions, release commits, platform digests, worker counts, or timeout values from `marketplace.toml` into scripts or prose.

If generation behavior changes, additionally run the affected pack through the matching real consumer/runtime court and prove replay/idempotency. Marketplace qualification cannot substitute for domain execution.

## Level-5 changes

A Level-5 promotion is a closure claim over seven dimensions plus Diátaxis, not a version-label change. Provide evidence for semantic source, admission/negative witnesses, manufacture, claimed execution boundary, receipt/replay, authority fencing, composition/class closure, and Tutorial/How-to/Reference/Explanation correspondence.

`pack-maturity-pack` may supply generic mechanical regeneration/receipt/Diátaxis infrastructure. It cannot supply missing domain facts or external execution evidence.

## Documentation changes

Place learning journeys in `docs/tutorials/`, task recipes in `docs/how-to/`, exact contracts in `docs/reference/`, and architecture/rationale in `docs/explanation/`. Do not collapse the quadrants into one giant README.

`docs/book.ttl` is the canonical mdBook navigation source. `docs/SUMMARY.md` is generated by the Pages manufacturing path and must not be edited as source.

When a contract changes, update every affected Diátaxis page/governance surface in the same dependency-closed transition. Avoid volatile copied values when a canonical executable source exists.

## Consolidation changes

Before deleting/merging packs, compare semantic authority, generated target ownership, admission/refusal law, runtime boundaries, receipts, authority ceilings, and consumers. Prefer reversible factoring: canonical ontology → capability modules → umbrella/profile → deprecation → deletion only after migration evidence.

See [`docs/how-to/consolidate-a-pack-family.md`](docs/how-to/consolidate-a-pack-family.md).

## Pull requests

Explain what changed, why, exact base/head, affected packs/classes, provenance, commands/exits, generated status, positive/negative witnesses, receipts/replay, authority ceiling, consolidation/compatibility effect, falsifiers, rollback, residual boundaries, and scoped standing. PR CI remains read-only evidence.

Do not claim ALIVE from queued metadata or historical success at another subject.
