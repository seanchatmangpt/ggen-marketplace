# ggen-marketplace v2030.1.1 — PRD / ARD

**Repository:** `seanchatmangpt/ggen-marketplace`  
**Ecosystem role:** pack-marketplace / accumulated executable knowledge  
**Depends on:** `ggen`  
**Release:** Chatman Ecosystem v2030.1.1  
**Standing conferred:** `UNKNOWN`.

## Product requirement

`ggen-marketplace` SHALL be the canonical, reviewable corpus of reusable executable knowledge from which Chatman Ecosystem capabilities are manufactured. By v2030.1.1, a pack is not merely a template bundle: it is a bounded semantic manufacturing unit capable of declaring meaning, constraints, projections, tests, refusals, provenance, and qualification requirements.

The repository SHALL enable the ecosystem to accumulate solved engineering knowledge once and reuse it across software, clouds, marketplaces, security frameworks, processes, data/AI platforms, and enterprise systems.

## Required capabilities

1. Preserve `marketplace.toml` and pack-local canonical source hierarchy; consumer outputs remain consequences, not marketplace source.
2. Define packs through explicit identity, ontology, queries/templates, admission gates, capability bounds, dependencies, and provenance.
3. Support pack families for cloud services, marketplace commerce, protocols, security/control frameworks, process intelligence, observability, enterprise applications, AI/data platforms, and scientific/engineering knowledge.
4. Prefer public ontologies and standards; local vocabulary extends rather than silently replaces equivalent public meaning.
5. Qualify packs deterministically against the exact admitted marketplace configuration and ggen runtime.
6. Expose machine-readable catalog/fingerprint data without maintaining a second hand-authored catalog.
7. Distinguish repository qualification from live consumer/provider execution.
8. Preserve positive, negative, refusal, replay, and provenance fixtures sufficient for downstream admission.

## Architecture requirements

```text
public knowledge / standards / papers / provider contracts
        -> pack ontology + provenance
        -> pack admission gates
        -> ggen query/template projection
        -> consumer artifact
        -> consumer/runtime verifier
        -> receipt
```

A pack MAY manufacture SELECT/CONSTRUCT knowledge. It SHALL NOT gain ambient production DO authority. Qualification proves the bounded pack contract only.

## v2030 marketplace fabric

Marketplace packs SHALL model canonical commercial concepts such as Offer, Contract, Entitlement, Usage, Meter, Price, Deployment, PrivateOffer, Renewal, Cancellation, Receipt, and provider projection. AWS, Microsoft, Google, Oracle, IBM, SAP, Salesforce, ServiceNow, Snowflake, Databricks, Alibaba, Atlassian, GitHub, and future marketplaces SHALL be modeled as projections rather than independent product truths.

## Acceptance for v2030.1.1

- catalog generation is deterministic and repeatable;
- every admitted pack has exact source/provenance identity;
- pack dependencies close without implicit edges;
- generated consumer artifacts can be reproduced from pack source through pinned ggen inputs;
- qualification has negative/tamper coverage;
- representative cloud + marketplace + protocol packs can manufacture their declared surfaces;
- live-provider claims remain bounded until the resulting consumer is executed at the real boundary;
- no CI path rewrites canonical pack source to obtain green status.

## Falsifiers

The architecture is falsified if marketplace/catalog metadata must be duplicated by hand; if a pack's output cannot be traced to ontology/query/template source; if qualification is used as proof that a cloud or SaaS provider actually accepted an operation; or if pack source embeds hidden production authority.

## Ecosystem contract

`ggen-marketplace` stores reusable manufacturing knowledge. `ggen` renders it. Owning formal/runtime systems admit it. BRCE-governed systems actuate it. Receipts establish standing only for the exact boundary actually executed.
